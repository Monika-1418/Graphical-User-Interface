The STAR-System API is provided as a set of cross-platform libraries and header files for use with the C programming language. The C++ API extends this to provide an object-oriented interface to STAR-System.

The C++ API is provided as a 'thin-wrapper'. Rather than being deployed as binary libraries, it is deployed as a set of C++ header files with a .hpp extension (the .hpp extension is to distinguish them from the .h header files in the C API). The classes in the C++ API are implemented inline within these header files and provide an object-oriented wrapper around the functions contained in the underlying C API. To utilise the C++ API one simply has to include the relevant header files into a development project to gain direct access to the classes they contain.

Because the C++ API is deployed as a set of header files only, it requires the presence of the C API on the target machine too so it can include and provide a wrapper around the functionality that it requires.

To make use of the C++ API one has to follow the standard procedure for installing and using the STAR-System API. This will install the standard C API libraries and header files onto the target machine along with header files for the C++ API.

To make use of the C++ API it is necessary to add references to the following paths in your development environment and/or compiler makefile(s):

  • The path to the header files for the STAR-System C API
  • The path to the C++ API header files
  • The path to the STAR-System libraries

Please see the main STAR-System documentation for further information about installing STAR-System, supported operating systems, and other information such as how to get started.

Summary of Main Sections in the API

Device information, transmitting and receiving packets.

Namespace(s): stardundee::com::starsystem::general
stardundee::com::starsystem::streamitems
stardundee::com::starsystem::channels
stardundee::com::starsystem::transferoperations
Representative classes: Device, Driver, Channel, Packet, TransmitOperation, ReceiveOperation

These namespaces contain classes which can be used to get a list of connected devices and drivers, transmit and receive traffic with those devices, and register for notification of events.

All traffic transmitted and received is done so over channels to devices. A channel to a device must be opened before traffic can be transmitted or received. When a device is in interface mode, a channel may correspond to a port on the device, e.g. all traffic transmitted over channel 1 will be sent over port 1 of the device. When a device is in router mode, a channel corresponds to an external port on the router. Channels can be opened to transmit traffic and/or to receive traffic. This allows one application to transmit traffic over a port, while another application receives from that port. Once an application has opened a channel to a device, no other application can open that same channel until it has been closed.

Device Configuration

Namespace(s): stardundee::com::starsystem::deviceconfig
stardundee::com::starsystem::deviceconfig::mk2devices
stardundee::com::starsystem::deviceconfig::mk2devices::brickmk2
stardundee::com::starsystem::deviceconfig::mk2devices::brickmk3
stardundee::com::starsystem::deviceconfig::mk2devices::pcimk2
stardundee::com::starsystem::deviceconfig::mk2devices::routermk2s
stardundee::com::starsystem::deviceconfig::mk2devices::pcie
Representative classes: DeviceConfiguration, Port, LinkPort, ExternalPort, ConfigPort, NetworkDiscoveryInfo, RoutingTableEntry

These namespaces contain classes which can be used to query the state of, and to configure devices. These devices may be connected to the local PC, or may be connected over a SpaceWire network. A number of functions common to all supported routing devices are provided, while additional functions are included which are specific to each device.

For example, there are functions for getting and setting the routing tables of all supported routing devices, and for starting and stopping each of the links on a routing device. These functions can be used with the SpaceWire PCI Mk2, SpaceWire-USB Brick Mk2, etc. Newer STAR-Dundee devices such as the PCI Mk2 and Brick Mk2 support a feature which causes the device to flash its LEDs when requested, in order to visually identify the device. This can be useful when there are multiple devices in a PC, or multiple devices on a network.

RMAP Packet Library

Namespace(s): stardundee::com::starsystem::rmap
Representative classes: RMAPPacketLibrary, RMAPPacket, RMAPReadCommandPacket, RMAPWriteCommandPacket

The RMAP Packet Library was provided with STAR-Dundee's older USB and PCI APIs. The Remote Memory Access Protocol (RMAP) is a protocol designed specifically for reading and writing memory over SpaceWire. Its simplicity and flexibility means that it can also be used for many other purposes. The Device Configuration API uses RMAP to read and write to registers of SpaceWire devices in order to configure them.

The RMAP Packet Library provides classes for constructing each type of RMAP packet, checking whether a packet is a valid RMAP packet, and accessing the fields in an RMAP packet.

Example Programs

The STAR-System C++ API comes with a number of example programs with source code. Some of these applications are described below.

Transmit and Receive Example

Provides an example of transmitting and receiving packets as described in the application note "Transmitting And Receiving Packets Using the STAR-System C++ API". This requires obtaining a list of devices present, opening a channel on a device, creating a packet to transmit on the channel, using a transmit operation to transmit the packet, using a receive operation to receive a packet, retreiving the packet data and displaying it.

STAR-System Test Program

The STAR-System Test program provides a number of common functions which may be performed when testing your hardware. These include loopback tests (transmitting packets out of one link and receiving them on another), double loopback tests (transmitting and receiving on two links at the same time), transmitting packets to another destination, receiving packets from another source, and transmitting and receiving files.

These features have been provided with STAR-Dundee's test programs for previous PCI and USB systems, although STAR-System Test is more powerful than previous incarnations. It allows you to run multiple instances of the software and, for example, transmit from one software instance and receive in another. It also allows you to perform loopback tests between two devices. For example, if you have two SpaceWire PCI Mk2 devices, you can connect a SpaceWire cable between them and transmit packets from one to the other.

The source code for STAR-System Test can be used as a basis for your own code, with numerous examples of transmitting and receiving packets provided. The software also provides a Get Version option, so you can find exactly which versions of the various modules of STAR-System you have installed, and which devices are connected to your PC.

Note that this is a C++ version of the original C implementation of STAR-System Test, and the source code of each can be used to compare the differences when implementing code using the C and C++ APIs.

Performance Tester

STAR-Dundee strives to get the best performance from our APIs, drivers and devices. For this reason, we use a number of tools to determine the throughput and latency we can achieve. The Performance Tester is one of those tools. It provides options to transmit and/or receive packets at the fastest possible rate achievable, using various packet sizes or random packet sizes, and to test the latency when transmitting and receiving. While the tests are being executed, the CPU usage is monitored and recorded, including the total CPU usage and the application's CPU usage. The rates, average packet transmission time (latency) and CPU usage achieved can be written to file, and the results files can then be imported in to a spreadsheet such as Microsoft Excel to graph data rates, packet rates, etc.

If you are interested to see the throughput that can be achieved using STAR-System with a particular packet size, for example, then STAR Performance Tester can give you that information. The source code provided can be very useful in your own code, as it is designed to achieve the best possible performance from the API and drivers.

Note that you can use the Performance Tester to transmit packets, receive packets, or to do both. If you set the Performance Tester to only transmit, you will need another application to receive those packets, or to configure hardware to drop the packets. It is a similar situation when receiving. You can run two instances of the Performance Tester, either on the same PC or on different PCs, with one instance transmitting and a second instance receiving.

Also note that the latency times displayed are the average of the total time that it takes to transmit and receive a packet. This includes the time that the packet is on the SpaceWire link, so is larger than the actual latency introduced by the software. The data and packets rates shown are the rates at which packets are being transmitted on the link.

The Performance Tester will accept the test parameters as command line arguments. Just pass all the arguments that the application will ask for in order. For string arguments, you can include these in quotes if they contain spaces, or specify two quotes if an empty string is to be provided (e.g. an address path with no bytes).

Note that this is a C++ version of the original C implementation of the Performance Tester, and the source code of each can be used to compare the differences when implementing code using the C and C++ APIs.

Device Configuration Examples

The Device Configuration Examples illustrate functions such as the following: getting and setting routing table entries, getting and setting the properties of ports, starting and stopping links, and enabling and disabling interface mode of the PCI Mk2.

RMAP Packet Library Examples

The RMAP Packet Library Examples illustrate how to create RMAP packets of various types (such as read command packets, write command packets). An example is also provided of implementing a simple RMAP initiator as described in the application note "Implementing A Simple RMAP Initiator Using The STAR-System C++ API". This involves creating an RMAP read command to read the value from the general purpose register on a device; creating a packet to transmit the read command; using a receive operation to receive the read reply, extracting an RMAP read reply packet from the data received, displaying the data read.
